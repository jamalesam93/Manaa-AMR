## 2024-05-15 - [Insecure LocalStorage Deserialization]
**Vulnerability:** Several utility functions (`getDailyChallenge`, `getDailyChallengeStats`) and the app context (`AppContext.jsx`) parse data from `localStorage` using `JSON.parse` without `try-catch` blocks or schema validation.
**Learning:** This exposes the application to DoS attacks through local storage injection. If the stored data becomes invalid JSON, the parsing throws an error that crashes the component or the whole application, leading to a persistent unhandled exception until `localStorage` is cleared manually.
**Prevention:** All data retrieved from `localStorage` must be parsed within `try-catch` blocks, strictly validated for expected types (e.g., `Array.isArray`, `typeof === 'object'`), and ensure `console.error` calls are restricted to development (`import.meta.env.DEV`).
## 2024-06-20 - [URL Sanitization Bypass]
**Vulnerability:** The `isSafeUrl` function failed to block dangerous `data:` and `file:` protocols, enabling potential XSS or unauthorized local file access. Furthermore, passing an array to the URL constructor bypasses early string checks because the `URL` constructor implicitly converts arrays to strings.
**Learning:** Checking for `javascript:` and `vbscript:` is not enough; `data:` and `file:` are equally dangerous attack vectors. Additionally, JavaScript's `URL` constructor automatically coerces inputs to strings, which can lead to unexpected URL construction from non-string objects.
**Prevention:** Always restrict URL schemes using an explicit blocklist (or prefer an allowlist) covering `data:`, `file:`, `javascript:`, and `vbscript:`. Crucially, fail fast for any input where `typeof url !== 'string'` prior to invoking the `URL` constructor.
