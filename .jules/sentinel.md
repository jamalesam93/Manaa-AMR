## 2024-03-24 - [Avoid CSP Breakage & Implement Insecure Deserialization Protections]
**Vulnerability:** Attempted to add a highly restrictive CSP which would break Vite dev server and external requests, leading to application breakage. Also identified unprotected `JSON.parse` operations on `localStorage` inputs and production leak of internal state via `console.error`.
**Learning:** Blindly applying restrictive CSPs, especially with meta tags and 'unsafe-inline' requirements for modern tooling, causes huge regressions and counts as security theater. Also learned to prioritize failing securely: unprotected `localStorage` payloads can lead to unhandled exceptions and crashes (DoS risks) when deserialized.
**Prevention:** Rather than a strict meta-tag CSP that breaks the application, use `import.meta.env.DEV` to mask sensitive logs from end-users. Validate all serialized `localStorage` payloads through `try/catch` and expected type validations (e.g. `Array.isArray()`) to ensure resilience against state poisoning.
