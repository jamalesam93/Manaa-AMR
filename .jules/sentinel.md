## 2025-02-28 - [DOM-based XSS Prevention in Media Components]
**Vulnerability:** The application was directly assigning unvalidated user-controlled strings to dynamically created download links (`a.href`) and media source attributes (`video.src`, `audio.src`, `img.src`) in `MediaPlayer.jsx` and `ImageGallery.jsx`. This exposed the application to DOM-based Cross-Site Scripting (XSS) via dangerous schemes like `javascript:` and `vbscript:`.
**Learning:** React's built-in XSS protections do not cover dynamic assignments made directly to the DOM API (e.g., `document.createElement('a').href = url`), nor do they fully protect against malicious schemes in standard JSX `src` attributes unless an explicit allowlist is used.
**Prevention:** A strict URL scheme allowlist strategy must be implemented using a utility function (`getSafeUrl`) to validate all dynamically assigned URLs. Legitimate media handling often requires `blob:` and `data:` schemes, so these should be explicitly permitted alongside `http:` and `https:`, while all other schemes (especially `javascript:`) should be blocked or safely substituted.
