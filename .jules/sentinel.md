## 2025-02-12 - Prevent DOM-based XSS in Media Downloads
**Vulnerability:** A potential DOM-based Cross-Site Scripting (XSS) vulnerability was present in the `ImageGallery.jsx` and `MediaPlayer.jsx` components. The components were dynamically creating `<a>` elements and assigning their `href` attribute directly from user-supplied or external media `src` properties without validation. An attacker could potentially inject a `javascript:` URI (e.g., `javascript:alert(1)`) into the media source, which would execute arbitrary JavaScript in the context of the user's session when the download link was automatically clicked.
**Learning:** Native `<a>` tag `href` assignments followed by a programmatic `.click()` are dangerous when the URL source is unvalidated, as the browser will happily execute dangerous protocols like `javascript:`. Using `URL` parsing to validate protocols is essential, even for seemingly innocuous "download" links.
**Prevention:** Implemented a new utility function `isSafeUrl` in `src/utils/security.js` that uses the native `URL` constructor to reliably parse and validate the protocol of the URL, ensuring that only safe protocols (e.g., `http:`, `https:`, `blob:`) are allowed while denying known dangerous protocols (`javascript:`, `vbscript:`, `data:`, `file:`). This utility must be applied to all dynamic `href` or `src` assignments where the source is not strictly controlled.
