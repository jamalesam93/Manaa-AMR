## 2024-04-18 - Prevent DOM-based XSS in Media Components
**Vulnerability:** The application was directly setting user-controlled or external API-provided data to `src` attributes and dynamic `href` download links (e.g., `link.href = image.src`) in `ImageGallery` and `MediaPlayer` components without any validation. This exposed a risk of DOM-based XSS via `javascript:` or `vbscript:` schemes.
**Learning:** React prevents XSS in text nodes, but assigning URLs directly to DOM properties (like `link.href`) or React attributes like `src` can still lead to script execution if the URL scheme is dangerous. Also, validation logic must be careful with types: failing open (`return true`) for non-string inputs can be bypassed if an attacker passes an array (e.g. `['javascript:alert(1)']`) which is then implicitly converted to string by the DOM.
**Prevention:** Implement and use robust URL sanitization (e.g., `isSafeUrl`, `getSafeUrl`) that explicitly blocks dangerous schemes (and strips control characters/whitespace to prevent bypasses), and ensure that unexpected input types fail securely (return `false`). Use these helpers uniformly on any dynamically constructed `src` or `href` attributes.
