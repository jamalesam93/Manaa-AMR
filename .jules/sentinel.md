## 2024-04-07 - Prevent DOM-based XSS in Media Downloads
**Vulnerability:** The `handleDownload` functions in `MediaPlayer.jsx` and `ImageGallery.jsx` dynamically create an `<a>` element, assign an unvalidated `src` property to the `href` attribute, and simulate a click. If an attacker can control the `src` property (e.g., via malicious input rendering as `javascript:alert(1)`), they can execute arbitrary JavaScript in the user's session when the download is triggered.
**Learning:** Even internal props (`src` of media) must be validated before being used in sinks that execute code, like the `href` attribute of an anchor tag, to prevent DOM-based XSS. The memory explicitely stated: "To prevent DOM-based XSS (specifically `javascript:` URI execution), all dynamic URL assignments to `href` or `src` attributes—particularly for download functionality in components like `MediaPlayer` and `ImageGallery`—must be validated using the `isSafeUrl` utility from `src/utils/security.js`."
**Prevention:** Implement and use a centralized `isSafeUrl` validation utility for all dynamic URL assignments to `href` and `src` attributes, rejecting risky protocols (`javascript:`, `vbscript:`) and unsafe `data:` URIs.
