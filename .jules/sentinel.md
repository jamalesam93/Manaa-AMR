## 2024-05-05 - DoS and Information Exposure via Vite Environment Variables in ErrorBoundary
**Vulnerability:** The ErrorBoundary component used Node.js `process.env.NODE_ENV` to determine whether to show detailed stack traces. In Vite, `process.env` is not injected in the browser by default, so referencing it causes a ReferenceError. This crashes the ErrorBoundary component itself when an error occurs, leading to a complete application failure (Denial of Service) instead of a graceful fallback. Furthermore, the `console.error` call lacked an environment check, leaking detailed error traces to the browser console in production.
**Learning:** Vite applications must use `import.meta.env.DEV` or `import.meta.env.PROD` for environment detection. Relying on `process.env.NODE_ENV` outside of the backend or specific build contexts leads to unhandled runtime exceptions. Error boundaries must be extremely robust, and any secondary exceptions within them are fatal.
**Prevention:** Always use Vite's `import.meta.env` for environment checks. Ensure that any error logging to the console (e.g., `console.error` in `componentDidCatch`) is wrapped in environment checks so production logs do not expose internal stack traces or vulnerability details.
